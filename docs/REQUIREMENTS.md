# 要件定義書 — Threads自動投稿ツール

## ゴール
「仕込み中にスマホで写真とひとことを放り込む → 翌朝、整った投稿として自動で出る」

## 発信の目的（重要）
一般消費者向けの日常発信ではなく、**卸クライアント（カフェ・ホテル・飲食店）の開拓**が目的。
読者はオーナー・仕入れ担当者。すべての投稿は「この店は卸相手として信頼できるか」に答える内容にする。
- 味の自慢より「安定供給できること」の証明を優先
- 相手の商売目線（原価・オペレーション・メニューへのはまり方）で書く
- 投稿の締めは押し売りせず「卸のご相談はDMで」程度の軽い導線に留める

## 運用フロー
1. ネタ投入（人間・随時）: 管理画面から写真＋メモ1行をストックに追加
2. 文案生成（AI・投入時）: パン屋の一人称の語り口でThreads向け短文に整形。人間が確認・修正可
3. 自動投稿（システム・定時）: 毎朝の指定時刻にストック先頭の「承認済み」投稿を公開
4. リプライ対応（人間・手動）: アルゴリズム対策として返信は必ず手動

## フェーズ1: 投稿ストック管理画面（実投稿なし）
- Firebase RTDB に posts ノード: { text, imageUrl, status, scheduledAt, createdAt, insights }
- status: draft（下書き）→ approved（承認済み）→ published（投稿済み）
- 一覧表示（scheduledAt順）、追加、編集、削除、承認ボタン
- 写真は Firebase Storage にアップロードし公開URLを保存
- スマホファーストUI。追加フォームは「写真＋テキスト1行」のみ

**完了条件**: iPhoneから写真付きネタを追加し、承認状態を切り替えられる

## フェーズ2: 文案生成
- Cloud Functions に generateCaption 関数（Anthropic APIプロキシ）
- 入力: メモ1行＋（任意で）ネタのカテゴリ
  - カテゴリ: 供給実績（納品体制・数量）/ 商品と用途提案（相手のメニューへのはまり方）/
    製造現場（品質管理・量産体制が伝わる裏側）/ 柔軟対応（サイズ変更・オリジナル配合・小ロット）/
    事例紹介（既存卸先での使われ方 ※先方の許可必須）
- 出力: Threads向け500字以内の文案。ハッシュタグは最大2個
- 語り口プロンプトは functions/prompts/voice.md に分離し、調整しやすくする
  - voice.md の方針: 職人の一人称だが読者はオーナー・仕入れ担当。
    「今日も焼けました」ではなく「毎朝◯時納品でこの状態を維持しています」の目線。
    数字（納品時数・本数・対応ロット）を入れられる時は必ず入れる
- 管理画面に「文案を生成」ボタン → 結果をtextに反映（上書き前に確認モーダル）

**完了条件**: メモ1行から自然な投稿文が生成され、編集して承認できる

## フェーズ3: 定時自動投稿
- 投稿枠は1日3回: 07:00 / 12:00 / 19:00 JST（管理画面の自動割り当てと同じ枠）
- Cloud Scheduler → publishScheduled 関数（毎日 07:00 / 12:00 / 19:00 JST に実行）
- approved かつ scheduledAt が到来している先頭1件を投稿（1回の実行で1件のみ）
- Threads API 2段階投稿（コンテナ作成 → 公開）。画像があれば IMAGE、なければ TEXT
- 成功時 status を published に更新、Threads投稿IDを保存
- 失敗時はリトライ1回、それでも失敗なら status を error にしてエラー内容を保存
- dry-run モード（環境変数 DRY_RUN=true で実投稿せず payload をログ出力）

**完了条件**: dry-run で payload が正しいことを確認後、実投稿1件が成功する

## フェーズ4: トークン自動リフレッシュ
- refreshToken 関数（Scheduler 週1）
- GET /refresh_access_token で長期トークンを更新し、RTDB の config に保存
- 有効期限残り日数を管理画面に表示。残り7日未満で画面に警告表示

**完了条件**: リフレッシュ後も投稿が成功し、期限が画面で確認できる

## フェーズ5: インサイト週次レポート
- fetchInsights 関数（Scheduler 週1）: published 投稿の views/likes/replies/reposts を取得
- 管理画面に簡易ダッシュボード（直近4週の投稿別 views、カテゴリ別平均）
- 「伸びたカテゴリ」が一目でわかること

**完了条件**: 先週分の数値が画面で見られる

## 事前に手動で済ませること（開発開始前）
1. 投稿先のThreadsアカウントを決める（個人アカウントでOK。Instagramプロアカウント化は不要。
   試運転は個人アカウントで行い、後で専用アカウントへ切り替える場合は再連携するだけ）
2. Meta for Developers でアプリ作成、ユースケース「Threads APIにアクセス」を選択
3. 認証フローで短期トークン取得 → 長期トークン（60日）に交換
4. App ID / App Secret / 長期トークン / ThreadsユーザーID を控える
5. Firebase プロジェクト作成（RTDB + Storage + Functions 有効化、Blazeプラン必要）→ 済

## フェーズ6: 分析フィードバック（設計方針は docs/AGENT_DESIGN.md 参照）
- フェーズ5で貯めたインサイトをAIが分析し、「効いてるワード・型」を抽出
- 分析結果を voice.md（生成プロンプト）の改善に反映するループを作る
- 「生成→承認→投稿→計測→学習」のミニ自律エージェント構成。最終操作は常に人間承認

## 今後のアイデア（優先度未定）
- **ストックテンプレ**: よく使う文の型をアプリ内に保存し、ネタ追加時に選んで使える
- **写真保管**: 撮った写真をアプリ内にライブラリとして貯めておき、投稿ネタ作成時に選べる
- **リプライ/DM検知**: 新着を検知して通知＋返信下書きを生成（送信は必ず人間が行う）

## 対象外（今回はやらない）
- 複数アカウント対応
- リプライの自動返信（アルゴリズム上も規約上もやらない）
- Instagram / X への同時投稿（将来検討）
