# 自律エージェント設計メモ（Threads投稿ツール向け）

作成日: 2026-08-09 / Claudeとの会話まとめ

## 1. 自律エージェントとは
目標だけ渡せば「手順分解 → ツール実行 → 結果を見て次の判断」を自分でループするAI。
得意なのは: 試行錯誤が必要な作業 / 多段の定型作業 / 調べてまとめる / 定期的に回る仕事。

弱点: 目標が曖昧だと迷走する。長時間放置で誤りが蓄積する。
→ 対策は「完了条件を先に書く」「チェックポイントを残す」。
お金・お客さん・公開物が絡む最終操作は人間承認にする。

## 2. Threads投稿ツールへの適用
単なる予約投稿ではなく、以下のループを目指す:

1. ネタ元（新商品・季節・卸売実績）から投稿文を複数案生成
2. Threads APIで予約・投稿
3. 数日後にインプレッション・いいね・返信を取得
4. 反応の良かった型を分析し、次週の生成プロンプトに反映

B2B卸売獲得が目的なので、返信/DM検知 → 通知 → 返信下書き生成 → **送信のみ人間承認**が実用的。

### 注意点
- 完全自動投稿は事故のもと。最初は「下書き生成→承認→投稿」の半自動から（現行設計どおり）
- Threads APIのレート制限・投稿数制限（250件/日）に対応したリトライ設計
- スパム的自動化（大量フォロー・無差別返信）はBAN対象。自コンテンツの自動投稿はOK
- リプライの「自動送信」はやらない（検知と下書きまで。送信は人間）

## 4. 業界の現在地（2026年時点の参考）
- 「完全AIのみ」の放置運用は失敗例が多い。成果を出しているのは「エージェント＋人間の承認ポイント」構成
- Gartner予測: エージェントAIプロジェクトの40%が2027年までに中止見込み（コスト増・価値不明・リスク管理不足）
- 成功組織の共通点: 監視・監査ログ・停止スイッチ・human-in-the-loop

→ 本ツールの「生成→承認→投稿→計測→学習」構成はこの成功パターンのミニ版。
停止スイッチ = DRY_RUN環境変数 / 承認フロー。監査ログ = Cloud Functionsログ + 投稿履歴(RTDB)。
